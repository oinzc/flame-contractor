# Flame Contractor 独立 Android 版 v2B 实施计划

> **For agentic workers:** Each track operates on an isolated git branch created from `feat/android-v2b` (after Stage 0 Foundation commit) and strictly touches only its owned files.

**Goal:** 在独立 Android 客户端（Room `version = 4`）落地本地图片发送（`TemplateType.IMAGE`）与多账号切换/独立后台串行调度（AndroidX WebView `ProfileStore`），完整保留防重发、不改 `streak_days` 与公开仓隐私安全边界。

**Architecture:**
1. **Stage 0（公共基座，已先合入 `feat/android-v2b`）**：升级 Room 至 `version = 4`（`TemplateType.IMAGE`、`MessageTemplateEntity.imagePath`、`MIGRATION_3_4`、多账号 DAO）、`FileProvider` + `TemplateImageStore`、`core/account/`（`WebViewProfileRegistry`、`PendingProfileCleanupStore`、`ActiveAccountStore`、`AccountManager`）及最小跨模块共享参数扩展（`LocalNotifier.EXTRA_ACCOUNT_ID`、`ExecutionLiveState.activeAccountId`、`ScheduleCoordinator.inspectNextAutoScanAt(..., accountId)`、`ExecutionForegroundService.enqueueStructureProbe(..., accountId)`）。
2. **Track 1 (`v2b-exec`)**：`DesktopWebViewFactory` 多 Profile 绑定、`DouyinJsScripts` 上传 DOM/DataTransfer/顶层可见弹窗正则按钮（`^发送(?:\s*[（(]\d+[)）])?$` 兼容 `"发送（1）"`）、`DouyinWebExecutor.sendImage` 双路径传图与确认、`LoginWebViewActivity` 账号级 Cookie 隔离清理。
3. **Track 2 (`v2b-sched`)**：`FlameApplication` 冷启动延迟销毁已删 Profile、`LocalNotifier` 多账号 Notification/PendingIntent 隔离、`ScheduleCoordinator` 遍历所有账号聚合最早闹钟与分别派发、`ExecutionForegroundService` 联合去重队列（`(action, accountId, targetId)`）与多账号前缀告警。
4. **Track 3 (`v2b-backup`)**：`BackupModels`/`BackupCodec`/`BackupManager` 兼容导入导出 `type = "image"`（导出省略 `"image_path"` 键防清桌面路径；导入保留绑定并统计 `missingImageTemplateCount`）、`SanitizedDiagnosticsBuilder` 补充 `totalAccountCount`、`SettingsViewModel`/`SettingsScreen` 按 `accountId` 作用域隔离。
5. **Track 4 (`v2b-ui`)**：`AppContainer` 注入基座依赖、`TemplatesViewModel`/`TemplatesScreen` 图片选图预览与缺图提示、`Targets`/`Today`/`History` 按 `accountId` 绑定与防扫描快照跨号串入、`AccountManagerDialog` + `AdaptiveNavShell` 全局切换栏 + `MainActivity` 通知切号直达路由。

**Spec:** `docs/superpowers/specs/2026-11-23-android-v2b-design.md`

**Requirements:**
1. `DesktopWebViewFactory`: 增加 `profileName: String = WebViewProfileRegistry.DEFAULT_PROFILE_NAME` 与 `webChromeClient: WebChromeClient? = null`；非默认 Profile 在访问 `settings` / `loadUrl` 前调 `WebViewCompat.setProfile`；使用 `WebViewProfileRegistry.cookieManagerForProfileName(profileName)` 替代 `CookieManager.getInstance()`。

   - `buildProbeImageUploadDomJs(bundle)`：探测 `.semi-upload-add` 坐标与 `input[type="file"]` 数量；
   - `buildInjectImageDataTransferJs(bundle, imageBase64, fileName, mimeType)`：解码 Base64 → `File` → `DataTransfer` 赋值 `input.files` → 重置 `_valueTracker` → 派发 `input`/`change`；
   - `buildInspectImageConfirmModalJs(bundle)`：仅检视最顶层可见 `.semi-modal, [role="dialog"]`；匹配 `IMAGE_DIALOG_SEND` 失败后正则匹配文本 `^发送(?:\s*[（(]\d+[)）])?$` 的可见 `button, [role="button"]`（实测按钮为 `"发送（1）"`）；
   - `buildClickImageModalSendJs(bundle)` 与 `buildDismissImageModalJs()`。
3. `DouyinWebExecutor`:
   - `withOffscreenSession` 与外部调用入口均增加 `accountId: String = DEFAULT_ACCOUNT_ID`；
   - 新增 `sendImage(session, target, imageFile, imageContentUri, onStageSending, onStageConfirming)`：缺图直接 `FAILED_TERMINAL`；先走方案 A（`MotionEvent` 点 `.semi-upload-add` → `WebChromeClient.onShowFileChooser` 供 `imageContentUri`，兜底 JS `.click()`）→ 未见弹窗再降级方案 B（`DataTransfer`）；弹窗就绪后采样 `beforeMediaMultiset` → 切 `CONFIRMING` 点发送 → `SendConfirmer.confirmStickerAfterClick` 15s 确认（`SUCCEEDED` / `FAILED_RETRYABLE` / `UNKNOWN_REQUIRES_REVIEW`）。
4. `LoginWebViewActivity`: 按 `accountId` 绑定 Profile 与账号级清理 Cookie（仅单默认账号时才允许 `WebStorage.getInstance().deleteAllData()`）。

**Requirements:**
1. `FlameApplication.onCreate()`: 在任意 WebView 激活前调 `PendingProfileCleanupStore(this).cleanupPendingProfiles()`，且冷启动告警按多账号区分。
2. `LocalNotifier`: 在 `createLaunchPendingIntent` 放入 `EXTRA_ACCOUNT_ID`，并按 `(category, accountId)` 计算唯一 `requestCode` / `notificationId`（保留 `DEFAULT_ACCOUNT_ID` 为 `3001` 与 `3101..3106`）。
3. `ScheduleCoordinator`: 提取纯 JVM 聚合辅助逻辑以便无 Context 单测；`rescheduleAll()` 与 `evaluateAndDispatchIfNeeded()` 遍历 `accountDao.listAll()` 全部账号，分别取最早 `nextWakeAt`（`4101`）与最早 `nextAutoScanAt`（`4104`），并逐一派发到期账号；`inspectNextAutoScanAt(now, accountId)` 按指定 `accountId` 查询。
4. `ExecutionForegroundService`:
   - 按 `(action, accountId, targetId)` 对 `pendingIntents` 联合去重，允许不同账号串行入队；
   - 运行时与扫描快照更新 `ExecutionRuntimeBus` 的 `activeAccountId` 与 `latestScanSnapshotAccountId`；
   - 多账号模式下通知前缀加 `[${account.displayName}]` 并传 `accountId` 至 `localNotifier`；
   - 发送执行路径识别 `TemplateType.IMAGE` 并检核私有图片（待整合阶段接通 `executor.sendImage` 与 `withOffscreenSession(accountId)`）。
